# 이용권·구매 원장 연결 준비 · v0.3.3

현재 공개 테스트는 **실제 결제·구독·AI·광고가 꺼져 있다.** 게임과 추억집 파일 저장은 무료 체험이다. 이번 패치는 상품 안내, SQLite 이용 기록과 모의 영수증으로 검증하는 서버 경계를 준비한다. 실제 Apple/Google 영수증 확인, 로그인·구매 복원 UI, 환불 알림 서명 확인, 체크아웃 또는 스토어 SDK를 구현했다는 의미가 아니다.

## 상품 기준

| 상품 | 출시 준비 기준 | 원장 반영 |
| --- | --- | --- |
| Ultimate | US$7.99 / 월, 월 AI 300회, 내가 연 모임의 추억집·광고 제거 예정 | 확인된 구독 기간의 300회, 해당 기간의 권한 |
| 모임 추억집 | US$0.99, 한 모임 일회 구매 | 해당 모임의 승인 참가자가 이용하는 저장 권한 |
| AI 100회 / 300회 | 낱개 옵션 유지, 가격 미정 | 확인된 구매에 각각 100 / 300회, 잔여 유지 |
| 개인 광고 제거 | 낱개 옵션 유지, 가격 미정 | 구매자 본인의 광고 제거 권한 |

홈과 정상 종료 결과에 선택 상품 안내를 둔다. Ultimate와 추억집 두 카드를 보여주고 낱개 옵션은 접힌 설명에 넣는다. 현재 결제가 없는 테스트임을 첫 안내에 명시하며 결제 버튼이나 로그인 요구를 추가하지 않는다. 실제 상품 가격은 스토어 설정/현지화와 최종 출시 검토가 필요하다.

## 확인 경계

- 클라이언트의 `paid`, `credits`, `accountId`, `verified`, 테스트 모드 또는 상품 수량을 구매 증거로 사용하지 않는다.
- `createReceiptVerifier`는 서버 어댑터가 반환한 정규화 결과에 프로세스 내부 인증 표시를 붙인다. 원장은 그 표시가 없는 JSON이나 복사본을 거절한다. 표시 자체가 실제 스토어 검증은 아니다. 실제 어댑터가 없으므로 공개 서버에서는 이 구매 반영 경로를 사용할 수 없다.
- 구매자 ID는 인증된 계정의 불변 UUID여야 한다. 방 닉네임, 방 접근 키나 사용자가 적은 UUID로 유료 계정을 만들지 않는다. `resolveAccount`는 테스트에서만 주입하며 공개 서버는 계정 미연결로 처리한다.
- 모의 구매·계정 어댑터는 서버 테스트 코드에서만 주입할 수 있다. production에서는 서비스 생성과 모의 구매 원장 반영을 모두 거절한다. 환경변수나 HTTP 요청으로 켤 수 없다.
- 공개 `POST /api/rooms/:code/verify-purchase`는 승인 참가자라도 503으로 거절하며 구매/잔액을 만들지 않는다. 스토어 알림을 받는 공개 웹훅도 아직 없다.
- 모의 검증에서는 영수증의 실제 구매자와 서버가 확인한 모임 범위가 일치해야 한다. 상품과 수량은 공통 카탈로그에서 정하며 원문 영수증은 저장하거나 로그에 남기지 않는다.

## 횟수·권한 규칙

같은 공급자의 같은 거래 ID는 한 번만 반영한다. 복원은 사용한 횟수를 초기화하지 않는다. 다른 구매자/상품/기간으로 바뀐 동일 거래와 동일 구독 기간의 별도 거래 ID를 거절한다. 구독 원래 구매자의 바인딩은 갱신 때도 유지한다.

현재 활성 구독 기간의 월 이용분부터 사용한다. 이월하지 않으며 일찍 확인된 다음 기간은 시작 시각 전에는 사용할 수 없다. 기간이 겹쳐도 월 지급분을 합치지 않는다. 낱개 이용권 잔액은 구독 만료 후에도 남는다.

모임의 승인 참가자는 방장의 확인된 AI 잔액을 공유한다. 참가자의 개인 잔액을 임의로 대신 쓰지 않는다. 서버가 생성 전에 1회를 원장에 예약하고, 유효한 초안을 준비한 뒤 방 기록 저장과 원장 확정을 마쳐야 결과를 전달한다. 같은 요청은 한 번만 예약/확정하며 여러 방에서 동시에 요청해도 잔액을 초과하지 않는다.

실패·시간 초과·퇴장·종료·만료·이용권 회수에는 진행 중 예약을 한 번만 반환한다. 구독 만료나 환불로 없어졌던 권한을 반환으로 되살리지 않는다. 재시작 시 남은 예약은 취소하고 해당 요청 ID를 다시 외부 호출하지 않는다. 실제 공급자 비용 가능성이 있는 하루 시도 상한은 기존 AI 예산 파일에서 별도로 유지하며 이용권을 샀다고 올라가지 않는다.

확인된 환불은 거래를 회수하고 잔여 크레딧·진행 중 예약·광고/추억집 권한을 제거한다. 환불이 구매보다 먼저 도착해도 나중에 구매 복원으로 되살리지 않는다. 이미 받은 초안이나 내려받은 추억집 파일을 기기에서 회수하는 기능은 아니다.

추억집 권한은 **사진 저장 동의를 대신하지 않는다.** 사진 소유자/동의/정상 완료/현재 연결 참가자를 확인하는 기존 전달 규칙을 유지한다. 이번 공개 테스트의 미리보기·저장은 계속 무료이고 유료 내보내기 차단을 켜지 않는다. 스크린샷 방지나 유료 파일 보호를 보장하지 않는다.

## 저장·운영

Node 22.13+의 `node:sqlite`를 사용한다. `DATA_DIR/commerce.sqlite`와 WAL/SHM은 0600, 상위 비공개 데이터 폴더는 0700이다. 원장은 `rooms/` 밖에 있어 방 만료·사진 삭제가 이용권을 지우지 않는다. SQL은 바인딩된 prepared statement와 `BEGIN IMMEDIATE` 트랜잭션을 사용하며 `synchronous=FULL`, foreign keys, schema version을 적용한다. 훼손되거나 새로운 버전의 파일을 빈 원장으로 초기화하지 않는다.

원장에는 확인된 거래 식별자·구매자 UUID·기간·불투명 모임 범위·횟수 처리 상태·입력 해시만 저장한다. 원문 영수증, 방 코드, 닉네임, 접근 키, 사진, AI 입력/초안은 저장하지 않는다. HTTP/SSE에는 본인·모임의 집계 잔액과 권한 상태만 제공하고 원장이나 거래 원문은 공개하지 않는다. 현재 공개 모드에서는 계정/구매 권한을 모두 미연결로 표시한다.

현재 전용 사진 볼륨은 백업하지 않는다. 이번에 원장을 넣었지만 실제 구매 내역은 없고 유료 서비스/볼륨/백업을 추가하지 않았다. **실결제 전에는 원장을 사진과 분리해 복구 가능한 영속 저장소로 운영하고, 실제 계정·스토어 검증·서명된 환불·안전한 구매 복원·내보내기 권한 연결을 완성해야 한다.** 현재 사진 볼륨 전체를 백업하는 방식은 사용하지 않는다. 단일 인스턴스 테스트 준비이며 상용 결제 운영이 아니다.

## 검증

원장 18개, 서버 구매/공유 AI 통합 14개의 새 자동 검사를 추가한다. 실제 돈이나 영수증을 쓰지 않고 테스트 어댑터만 사용한다. 상품 안내 브라우저 검사는 결제/로그인/외부 공급자 요청 0개, 선택 카드 2개, 낱개 옵션, 무료 게임·추억집 유지, 320/390/768/1440 폭과 닫은 뒤 포커스를 확인한다. 기존 73개 서버 검사, 7개 추억집 검사, 멀티플레이·AI 초안·체험 브라우저 회귀도 유지한다.

공식 구현 참고: [Node 22.13 SQLite API](https://nodejs.org/download/release/v22.13.1/docs/api/sqlite.html), [SQLite 트랜잭션](https://sqlite.org/lang_transaction.html). 모델 비용이나 실제 결제 상품의 수익성 검증은 이번 범위가 아니다.
