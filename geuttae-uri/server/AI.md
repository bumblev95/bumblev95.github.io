# AI 초안 연결 준비 · v0.3.3

현재 공개 테스트에서는 **AI가 꺼져 있다.** 실제 OpenAI 요청, API 키 생성, 충전, 유료 전환을 실행하지 않았다. 연결 코드는 SDK의 fetch를 모의 응답으로 바꿔 검증했다. 체험의 예시 초안은 미리 작성한 고정 문구이며 AI 생성 결과가 아니다.

## 작성 흐름

1. 직접 출제는 계속 무료다. 장소·함께 한 일·작은 디테일 버튼으로 질문을 시작할 수 있다.
2. AI 연결 시 출제자는 기억(240자), 정답(60자), 질문 주제를 적고 외부 전송에 별도 동의한다. 사진은 입력에 포함하지 않는다.
3. 서버는 승인된 대기방 참가자만 허용한다. OpenAI에는 위 세 텍스트 필드만 보낸다. 사진·닉네임·방 코드·세션 토큰·요청 ID는 보내지 않는다.
4. 모델은 질문과 오답 보기 세 개만 제안한다. 서버가 출제자의 정답을 그대로 넣고 보기 위치를 정한다. 공개 후 이야기도 출제자가 적은 기억 그대로다. AI가 실제 기억을 보증하거나 사진을 분석하는 기능은 아니다.
5. 초안은 본인에게만 돌아오며 자동 등록하지 않는다. 작성 칸에 적용하면 정답 확인과 추억집 저장 동의가 다시 꺼진다. 직접 수정할 수 있으며, 질문·보기·정답·이야기나 사진을 바꾸면 정답 확인이 다시 필요하다.

## 비용과 중복 요청

- 기본 비활성. 키만 설정해도 호출하지 않는다. `AI_ENABLED=1`과 아래 네 설정이 모두 필요하다.
- 모임 전체가 성공한 초안 허용 횟수를 공유한다. 진행 중 요청도 자리를 예약해 동시 호출이 한도를 넘지 않는다. 검증된 초안이 완료되면 1회 사용한다. 작성 창을 닫아도 서버에서 초안이 완료된 경우에는 사용으로 기록될 수 있다.
- 시간 초과·공급자 오류·거부·잘못된 보기·대기방 종료·퇴장·만료에는 모임의 성공 횟수를 차감하지 않는다. 실패해도 공급자 요금이 발생할 수 있으므로 **서버 전체의 하루 요청 상한에는 모든 예약을 포함한다.** 18초 제한, 출력 1,000토큰 상한, SDK 자동 재시도 0회다.
- 동일한 참가자의 동일 요청 ID·동일 내용은 한 번만 호출한다. 같은 ID로 내용을 바꾸면 거절한다. 서버가 성공·실패·중단으로 기록한 ID를 다시 외부 호출하지 않는다.
- 정상 응답을 잃은 경우 같은 ID로 재시도해 프로세스 메모리의 본인 초안을 받을 수 있다. 서버 재시작·게임 시작·퇴장·종료 뒤에는 초안을 다시 받을 수 없다. 재시작 때 남은 진행 중 예약도 재호출하지 않는다.
- 하루 상한은 UTC 날짜 기준 `DATA_DIR/ai-budget.json`에 비공개로 기록하며 재시작으로 초기화되지 않는다. 파일 손상이나 과거로 움직인 시계에서는 호출을 차단한다. 현재 단일 인스턴스 전용이다.
- 요청 수·글자 수·출력 토큰 제한은 **달러 금액 상한이 아니다.** 실제 연결 전 모델의 현재 가격·접근 권한과 공급자 계정의 지출 제한을 확인하고 사용자와 비용 한도를 정해야 한다.
- 이 모임용 테스트 상한은 유료 크레딧이나 Ultimate 권한이 아니다. 브라우저의 결제 표시·테스트 플래그로 권한을 부여하지 않는다. v0.3.3에 구매/이용권 원장과 Ultimate 월 300회·낱개 잔액·모임 공유를 모의 어댑터로 검증했다. 실제 결제·계정·유료 권한 연결은 비활성이며 [COMMERCE.md](COMMERCE.md)를 따른다. 실제 AI 테스트의 하루 요청 상한은 구매 여부와 별도로 유지한다.

## 개인정보와 보관

AI 입력·초안은 room.json, 전역 비용 기록, SSE에 저장하거나 공개하지 않는다. room.json에는 입력의 해시·처리 상태·성공 횟수만 들어간다. 생성 결과는 서버 프로세스 메모리에서 같은 작성자의 중복 요청에만 사용하며 게임 시작·퇴장·종료·만료·서버 종료 시 지운다. 작성자가 적용하고 제출한 문제와 이야기는 기존 사진 퀴즈의 수명·공개 규칙을 따른다.

OpenAI Responses 요청은 `store:false`, 텔레메트리 비활성으로 보내고 공급자 오류의 원문을 로그/클라이언트로 전달하지 않는다. **`store:false`는 공급자의 모든 보관을 없애는 설정이 아니다.** 안전 점검 기록 등에는 공급자 정책이 적용된다. 별도 전송 동의 화면에 보관 안내를 연결한다.

## 실제 연결 전에 필요한 설정

기존 Railway 서비스의 보안 환경변수 설정을 사용한다. 키를 채팅·저장소·runtime-config.json·클라이언트 코드에 넣지 않는다. 배포된 키의 값은 읽거나 출력하지 않는다.

| 서버 환경변수 | 조건 |
| --- | --- |
| `AI_ENABLED` | 기본 미설정/비활성. 실제 호출 승인 후에만 `1` |
| `OPENAI_API_KEY` | 승인된 API 프로젝트의 비밀 키 |
| `AI_MODEL` | 현재 사용 가능한 Responses/Structured Outputs 모델을 확인해 지정. 기본 모델 없음 |
| `AI_DAILY_REQUEST_LIMIT` | 서버 전체 하루 시도 수. 명시적 정수 1–1,000 |
| `AI_ROOM_SUCCESS_LIMIT` | 모임 전체의 성공 초안 수. 명시적 정수 1–20 |

`AI_ENABLED=1`인데 필수 설정이 빠지거나 잘못되면 서버 시작을 중단한다. 현재 서비스에는 이 AI 환경변수들을 추가하지 않는다.

## 검증

`server/`에서 `npm test`, `node tests/ai-browser-qa.mjs`. 21개 추가 검사는 텍스트/동의 제한, 정답·이야기 보존, 실제 설치 SDK의 요청 모양, 재시도 금지, 비공개 저장, 여러 방의 하루 한도, 중복·동시 요청, 실패 횟수 반환, 게임 시작·퇴장·만료·재시작을 다룬다. 브라우저 검사는 모의 공급자로 수정·확인·적용과 휴대폰 폭을 확인한다. 실제 AI 결과의 품질·지연·가격·계정 접근은 아직 검증하지 않았다.

공식 구현 참고(2026-10-13 확인): [AI SDK 구조화 출력](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data), [OpenAI 구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs), [OpenAI 데이터 보관](https://developers.openai.com/api/docs/guides/your-data). SDK는 `ai@7.0.139`, `@ai-sdk/openai@4.0.93`에 고정하며 해당 패키지의 문서와 소스를 기준으로 작성했다.
